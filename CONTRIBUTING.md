# Contributing

Thanks for taking a look. This is a personal project, so it moves at the pace
of one person, but issues and pull requests are welcome and I do read them.

## Getting it running

You need Python 3.11+, Node 20+, and PostgreSQL 15+. The database is not
optional: most time-series queries use `date_trunc`, which SQLite has no
equivalent for.

```bash
# Backend
cd backend
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
export DATABASE_URL=postgresql://localhost:5432/analytics_dashboard
python reseed.py          # generates the synthetic dataset, takes a few minutes
python run.py             # http://localhost:5001

# Frontend
cd frontend
npm ci
npm run dev               # http://localhost:5173
```

`docker compose up` does the same thing with less setup.

## Before you open a pull request

```bash
cd backend  && python -m pytest -q     # 116 tests
cd frontend && npm run lint && npm test && npm run build   # 184 tests
```

CI runs both suites, a type-checked build, and a gitleaks secrets scan. The
backend job starts its own PostgreSQL service, so the cross-endpoint
consistency suite runs there rather than skipping.

## Two conventions worth knowing

**Numbers are measured, never generated.** This codebase used to report model
accuracy, churn scores, and confidence intervals from `random.uniform()`. All of
it is now derived from trained models on a holdout, and several tests assert
that endpoint output matches the model exactly rather than approximately. If you
find yourself reaching for a plausible-looking constant, that is the thing this
project is specifically trying not to do. Return `null` instead: the frontend
renders an honest blank.

**Time buckets follow one rule, defined once.** A period the window only partly
covers is not plotted, because a nine-day month sitting beside twelve complete
ones reads as a collapse. That rule lives in `backend/app/periods.py` and every
time-series endpoint calls it. Add an endpoint that buckets by time and it needs
`drop_incomplete_tail` too, or the pages will disagree with each other.

## The hosted demo

`https://analytics.ryansansbury.com` is a static snapshot, generated by
`scripts/refresh-demo.sh`. If you change an endpoint's shape or add a new one,
that script's `endpoints_for()` in `backend/scripts/snapshot.py` needs the new
path. A frontend test enforces this: it mounts every page under every date
preset against the snapshot and fails on anything the snapshot does not cover.
